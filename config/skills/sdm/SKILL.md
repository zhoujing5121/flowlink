# SDM 系统知识

## 系统概览

- 系统简称 SDM，OutSystems 应用 `GS_Purchasing_AP_SDM_Software`，测试环境 `apps-t-p1-outsystems.de.bosch.com`，开发环境 `apps-d-p1-outsystems.de.bosch.com`，生产环境 `apps-p-p1-outsystems.de.bosch.com`，支持中文和英文界面切换。
- OutSystems 形态：生成式 id（`Input_*`、`b2xx-*`、`l1_0-*`）、自定义下拉容器、侧边栏导航需 hover 激活；通用登录三分支与地标原则见 AGENTS.md，此处只记 SDM 特有事实。
- SDM 内多个业务模块，每个模块有自己的单据类型与业务流程；本 Skill 按「模块 → 业务流程」组织，新录制覆盖新模块/新流程时在对应小节补充。

## SDM 系统级惯例

- 列表页操作：状态筛选下拉 →「搜索」→ 勾选行 Checkbox（id 形如 `l1_0-…_0-Checkbox1`）→ 工具栏操作按钮（文本常带计数，如「出库 (1/1)」「销售 (1/1)」）。
- 状态筛选下拉选项文本格式：「生效/失效, 仓库 - <单据状态>」，必须逐字匹配（含空格与逗号）。
- 关键动作为两段式确认：操作按钮 → 弹窗「确认」；弹窗文案本身常含业务约束（如不可更改警告），是重要证据。

## 业务模块目录

### WasteProcessing（废弃物处理）——部分覆盖

业务对象：**废弃物处理单**，状态链：已称重 →（出库）→ 已出库 →（发运）→ 已发运 →（销售）→ 交易完成。每个业务动作推进一个状态，状态变化是切分业务阶段与验证业务生效的核心证据。

已记录的业务流程（登录后依次执行）：

1. **出库**：筛选「生效, 仓库 - 已称重」→「搜索」→ 勾选目标行 → 「出库 (1/1)」→ 填写 车号\*（`Input_TruckNumber*`）、运输单位、备注 → 「确认出库」→ 弹窗「确认」。完成标志：单据状态变为「已出库」。
2. **发运**：侧边栏进入发运入口 →（可选「打印」出厂单）→ 「确认发运」→ 填 出厂单号\* → 弹窗「提醒是否确认发运？一旦发运，所有信息将不可更改。确认」→ 「确认」。注意：发运后信息不可更改，核对/打印必须在确认前。完成标志：状态变为「已发运」。
3. **交易（销售）**：筛选「生效, 仓库 - 已发运」→「搜索」→ 勾选行 → 「销售 (1/1)」→ 向导式「下一步」多步推进（含必填输入，具体字段以页面实际为准）→ 提交。完成标志：生成销售单据/状态离开「已发运」，仅以页面实际结果证据为准。

各流程内的技术分段参考：筛选定位 → 表单/向导填写 → 两段式确认；登录三分支按 AGENTS.md 通用结构。

覆盖范围说明：当前仅覆盖本模块「出库→发运→销售」链路；模块内更早的流程（如单据创建、称重）与异常路径未记录，待补充。

## 已知坑（SDM 范围）

- 状态选项在自定义下拉容器中，可能需要先激活容器再选择；选项文本逐字匹配。
- 「确认出库」后的第二段弹窗「确认」必须保留，不要与操作按钮合并。
- 表单 placeholder 多为「请输入」，不能作为定位或断言依据；必填字段以 `aria-required` / 标签星号为准。
- OutSystems 生成 id 跨构建可能变化，元素引用优先 role+name，其次 `data-test-id`，id 仅在其稳定时使用。
