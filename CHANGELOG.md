# Changelog

All notable changes to FlowLink will be documented in this file.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) principles and this project uses semantic versioning.

## [Unreleased]

### Added

- **Process:** The canvas toolbar offers Flow | Swimlane dual views (radio menu, shared zoom/fit and one Expand/Collapse action-details switch) plus a clickable level switcher in the numbering-legend position (`01_Activity` / `01-01_Task` / `01-01-01_Action`, extending past three levels) — view, level, expand, and drill state are pure UI state on the recording item and never touch the Flow JSON; flat flows hide L1 and default to the step-detail view, identical to the previous rendering.
- **Process (levels):** `FlowGraph.buildGraph(flow, { level })` prunes the tree to the chosen group depth (groups at the level become leaf cards whose rows list their direct children; shallower groups with children become containers), edges lift to each endpoint's nearest level-ancestor card with parallel duplicates merged while keeping 是/否 branch labels, and back-edge detection re-runs on the lifted endpoints; levels at or below the deepest group depth render exactly like the full view. Double-clicking a group card drills one level in (its children become step cards and decision diamonds via `{ level: 1, stepUnits: true }`) with a breadcrumb to return; switching view or level resets the drill.
- **Process (swimlane):** `FlowGraph.buildSwimlane(flow, measure)` derives the matrix as pure data — columns are the flow's distinct effective targetSystems in appearance order plus an「未标注」fallback column, rows are L1 phase bands (sibling L1 groups targeted by the same condition merge into one band titled with the number range and the branch label, bare top-level steps get an ungrouped band), nodes are next-level task cards (L2 group cards or flat step cards) whose lane is the task's own tag, else its L1 ancestor's, else unlabeled, and grid coordinates are self-computed (no dagre); X6 renders column headers and phase bands as HTML label nodes over striped column rects, execution-order arrows with labeled branch and back edges, and Start/End sentinels.
- **Process (Expand):** The Expand switch expands the next-level detail lines inside cards — group rows gain their child items (group rows list child groups/steps with hierarchical codes, step rows show the step's 说明明细), swimlane task cards reveal the same details, and drill-view step cards show their detail line; collapsed cards keep the familiar rows-only look.
- **Process (replay overlay):** Group outline status aggregates at whatever level is on screen (any descendant failure red, all skipped gray — the per-node range spans its subtree so L1/L2 views aggregate automatically), and the swimlane view colors its task cards and dims untaken branch edges live during a run.
- **Tests:** Permanent regressions in `tests/swimlane-levels.test.mjs` cover `groupDepthOf`, level pruning with lifted/merged/back-recomputed edges (including >3-level extension and flat-flow equivalence with the full view), the `stepUnits` drill derivation, and `buildSwimlane` columns/lane inheritance/sibling band merge/placement/flat degradation/branch-edge resolution (conditions never become cards; their edges backtrack to the covering task).

- **Flow:** Nested multi-level grouping is a first-class contract (add-multilevel-grouping) — groups nest to any depth (L1 business stage ⊃ L2 technical group ⊃ steps), group and step ids share one Flow-wide namespace (duplicates rejected at save: `validateFlowContract` gained a `strict` mode wired to every write path — saveFlow, updateSteps, pending staging, refine/repair applies — while `loadFlow` stays lenient so legacy data with historical duplicates still opens and only fails on next save with the conflicting ids listed), empty groups are rejected on write, and groups carry an optional free-text `targetSystem` tag (explicitly declared in Zod so it survives save/load; a leaf step's effective system is its nearest ancestor's tag). Hierarchical numbering `01` / `01-01` / `01-01-01` (extending past three levels) is derived from tree position by the pure `FlowGraph.numberingOf(flow)` and shared by the Process canvas, Instruction group cards/step rows, and the Test list — step segments switch from three-digit (`01-001`) to the two-level scheme (`01-01`).
- **Process:** The canvas renders nested groups as hierarchical nodes — an outer group card visually contains its inner group cards and direct-step run cards (container bounds derive from the children bounding box after dagre layout; containers never participate in edges, so edges keep connecting cards and decision diamonds by execution semantics), flat flows render exactly as before, and group cards show a read-only `targetSystem` chip.
- **Instruction:** Group cards render recursively with hierarchy — inner group cards default to collapsed (Expand reveals their rows), the card head shows the hierarchical number plus tab/URL/branch badges, and a `targetSystem` chip offers inline editing (free text, saved through the strict `flow:updateSteps` validation with rollback on failure, empty clears the tag).
- **Instruction/Process menus:** Structural guards are nesting-aware — deleting a group with descendants asks for confirmation listing the affected step and nested-group counts, deletes the subtree, prunes groups left empty, and clears every condition branch reference into the removed steps; step delete/move/insert-after and group rename/move/re-record locate their target at any nesting depth (via the immediate parent derived from the flattened step path) instead of only top-level groups.
- **Prompts:** generation.autoSanitize and generation.refine now demand nested output — top level must be 2–6 L1 business-stage groups, L2 technical groups are optional inside them, depth is capped at three levels, and L1/L2 groups extract a `targetSystem` tag from recording evidence (URLs, domains, system names) omitting it when evidence is insufficient; the completion-mark splitting, four quality gates, SSO gate restructuring, variable templates, and `$ref` discipline are preserved, and malformed output (wrong top-level count, too-deep nesting, missing labels, non-string tags) fails generation with itemized issues instead of producing a half-refined flow (`validateGenerationStructure`).
- **Tests:** Permanent regressions in `tests/nested-grouping.test.mjs` cover the schema contract (nested save/reload round-trip, duplicate-id and empty-group rejection, lenient legacy load, unbounded depth, deep branch targets), the executor data boundary with zero executor code changes (flatten prefixes, outermost-group loop-limit key, branch-target resolution domain), `numberingOf` derivation (flat compatibility, nesting, >3 levels, shared positional sequence), the generation structure validator, the prompt-template disciplines, `buildGraph` nested container derivation, and the delete-with-branch-cleanup invariant.

- **Pi:** Built-in business knowledge for generation sessions via Pi native skills — apps bundle optional `config/skills/<name>/SKILL.md` files (strict frontmatter: name/description rules, no `allowed-tools`, no shell interpolation, description-total 8,000 / per-file 10,000 character budgets, violations fail the Pi request naming the file); skills are injected only into `pi:generateFlow`/`pi:repairFlow` sessions through a controlled skillsOverride (default/home/project discovery stays off), the skill bodies are never concatenated into prompts, and the model reads them on demand through the single restricted `read` tool whose name is locked (`read`) so Pi's native skills prompt section stays visible — readable paths limited to the built-in SKILL.md files and their explicitly listed `.md`/`.txt` references, with traversal/symlink/absolute/script/binary paths rejected and a 20,000-character per-request read budget that fails loudly instead of truncating; generation sessions assert their final tool registry contains exactly this one tool, advice/takeover/prewarm stay tool-less without skills, and the whole configuration surface (prompts.json, optional AGENTS.md with an 8,000-character cap appended as a framed domain-knowledge section at the central system-prompt assembly point, skills metadata) loads through one Pi config source boundary ready for a future admin page.
- **Prompts:** Generation prompts now teach a business-stage grouping method — track the business object the recording advances, split top-level groups only at verifiable completion marks (independent deliverable, state change, or handoff), name groups as verb + object business actions, close each stage at the four quality gates (entry reachable → authenticated → target content visible → business action effective, the last one asserted only when the element library contains result evidence), create `condition` branches only when they change what happens later, and state each group's completion mark in one `rationale` line — with the existing SSO gate restructuring, cleanup, variable-template protection, `$ref` discipline, and timeout/settle guidance preserved in systemPrompt, generation.autoSanitize, and generation.refine.
- **Tests:** A permanent regression suite (`tests/pi-knowledge.test.ts`, run by `npm test` through the new tsx devDependency) covers skills discovery/validation, path-safety of the restricted read tool, read budgets, and the generation-session tool-registry assertion against the real Pi SDK.

- **UI (Record):** The Record tab gains a "回放诊断" button — one click produces a plain-text diagnostics report (vendored `.replayer-*` stylesheet rule hits, replay iframe size/position/computed styles, per-tab event counts and full-snapshot counts, Replayer timing metadata, stage/tab-view layout values, load errors) with one-click copy, and it reports the actual state instead of throwing when the player is not mounted or failed to mount.
- **Process:** Right-clicking a group card (title or blank area) opens a group context menu — rename, move up/down, merge into next, delete, re-record this group, insert recording before/after — reusing the same operations, confirmations, and disabled states as the group action buttons; step rows keep their Modify/Break menu and blank canvas shows none.
- **Recording:** Full-page step screenshots are back without the flicker — each completed action step captures one full-frame PNG through the same CDP screencast single-frame mechanism as element crops, written to `record/screenshots/step-NNNN.png` and exposed as `stepScreenshots` in the recording metadata; the Record tab shows the wall per step again, recordings without screenshots (old data or `FLOWLINK_DISABLE_RECORDER_SHOTS=1`) show an explanatory empty state instead of placeholder tiles, and the switch itself never affects the recording.
- **UI (AI pane):** Two Test-failure presets live in the quick-actions strip — "Analyze last failure" sends the failure context to the pane on click (reusing the replay-failure advice wording) and "AI Continue" starts the single-step takeover loop — shown only while a failure result exists and no replay, test, or takeover is running.
- **UI (AI pane):** Refine messages render as removable preset chips above an independent free-text section: checked presets appear as chips (click × to uncheck), the submitted instruction is assembled as structured multi-line text (`- <preset>` per line plus the free text), and the chat entry shows the presets as chips plus the text section.

- **Process:** REFINED recordings evolve on a single track through staged pending updates — AI modifications of an already-REFINED recording (an AI-pane Refine with that single recording selected) land as a persisted pending version (`artifacts/<flowId>/pending.json`, survives restart; a newer refine silently replaces an older one without asking) and the AI pane's quick-actions strip shows Confirm/Discard (source and version in the tooltip); the generation message carries a structured Chinese change list (added/removed/changed steps with names, group add/remove/rename, gateway/branch changes) computed by the retained diff helpers — there is no graphical compare view. Confirm writes version+1 with the `.bak` backup after checking the pending's base version against the current one (mismatch refuses the Confirm and asks to regenerate); Discard deletes the pending immediately. Refining an original Record or merging several recordings still creates a new REFINED entry, and existing REFINED/REPAIRED entries are untouched.
- **Flow:** Every effective flow change now writes a history snapshot first — manual edits and proposal applies store the full previous version under `artifacts/<flowId>/history/` (`v<N>-<ts>.json` plus an `index.json` with source `human`/`refine-apply`/`repair-apply` and summary); the archive is write-only for now (no viewer UI) and a snapshot failure never blocks the save.
- **Test/Instruction:** While a pending update is unresolved, the Instruction tab and the Test progress header show a notice that edits and tests run against the current version (editing advances the version, so Confirm of the older pending will be refused and a regenerate is needed); the pending is resolved through the AI pane's Confirm/Discard.

- **Test:** Failed tests default to a token-saving AI-assisted loop: "AI Continue" lets the AI take over only the single failed step and then resumes program replay from the next step in the preserved browser state (already-executed prefix keeps its original results, executor reports the bypassed segment as skipped), bounded by 6 single-step interventions per test run; when the same step defeats the AI twice the loop stops and reports that step and its reason (the "AI: run all remaining steps" entry and the two-fail full-takeover fallback are gone — the single AI Continue button is the only entry, the remaining-mode capability stays UI-less), and the last-run summary and the automatic repair fire once when the whole loop has finished instead of per segment.

- **Pi:** AI takeover is branch-aware: before the agent starts, gate conditions are evaluated locally with the executor's own assertion logic to pick the step subsequence (skipped groups show as "Skipped" in the Test list, decisions are noted in the agent's task and the takeover summary), and `condition` steps are no longer handed to the agent to "make true".
- **Pi:** Takeover can now finish tab-based flows — `openTab`/`switchTab`/`closeTab` steps execute through the agent (only `upload`/`script` still stop the takeover with a clear reason), `manual` steps pause for user confirmation through the same panel replay uses, a takeover that needs a secret variable the Reference page never saved refuses to start with a clear error, and the overall budget is extended from 10 to 15 minutes.
- **Pi:** When a step fails twice, takeover degrades to free-run instead of stopping: the remaining steps become one goal task the agent completes on its own initiative, reporting each step as it lands (same AI badge in the Test list), with the takeover summary noting what was finished in free-run mode.
- **Pi:** Every completed takeover step captures structured element evidence from the live pages (tag/role/name/testid of interactive elements — never input values) into `ai-takeover.json`; the automatic repair injects this evidence into the refinement instruction and, for elements it matches in the library, prepends `source: "ai"` re-anchor candidates ahead of the recorded candidate chain (observed evidence stays immutable, output still passes the full schema contract).
- **Test:** After a repair creates a `REPAIRED-…` flow, FlowLink automatically re-runs the Test on it — at most 2 automatic rounds, shown as a "· 自动回跑 N/2" badge in the Test progress header and as messages in the AI pane; the original recording is never modified.

- **Instruction:** The Instruction tab is now a two-layer view: every step renders as one editable plain-language sentence (inline edit writes the step's `label`; empty restores the auto-generated wording) inside group cards headed by the business stage name with tab/URL and branch-entry badges, plus Manual/Automation source, optional, and manual-execution step badges.
- **Instruction:** Expanding a step opens a technical drawer of kind-specific structured fields — URL, value, key with modifier keys, wait condition and duration, assertions with condition branch targets, extract/upload/dialog/tab/scroll options, and the shared timeout, execution mode, isOptional, settle, and expect blocks; every edit saves to the Flow file through the validated `flow:updateSteps` contract (version bump and `.bak` backup) and rolls back with an inline row error when validation fails.
- **Instruction:** The drawer's target is a read-only evidence viewer (crop screenshot, candidate list with kind/score/source, fingerprint summary, nearby text) served by a new path-validated read-only `recording:artifactsPath` IPC; retargeting a step is deliberately limited to re-recording its group or referencing an element already captured in the Flow, and password-field values stay masked.
- **Instruction:** A per-step menu (⋯) offers editing the description, move up/down, delete, insert-after (reusing the Process manual step editor with the element library), and re-recording the step's group.
- **Recording:** Sessions now produce a true replayable screen capture: every tab's DOM events (rrweb) stream to disk as they happen, and the Record tab plays them back with play/pause, a seekable timeline, and per-tab switching (manual tab choice pauses auto-follow); known limits — cross-origin iframe/canvas content and closed shadow DOM internals are not captured, and non-password input values are recorded in plain text.
- **UI (Record):** Recordings made before the rrweb switch keep playing their existing webm video or frame captures unchanged (no data migration).

- **Process:** Contract-form condition steps (the trailing condition of a group) are extracted from their group card into a standalone diamond decision node connecting the two outgoing groups, so the graph reads like a real flowchart; groups that contained only a condition disappear into the diamond, and the missing branch of a decision ends at that segment's End.
- **Pi:** After an AI takeover finishes, the flow is optimized automatically in the background and saved as a new `REPAIRED-…` recording through the validated persist contract — the original flow and its test results stay untouched, there is no button (progress and the repair summary land in the AI pane chat); refinement now also round-trips `execution`/`settle`/`sourceFlowId` step fields instead of silently dropping them.

- **Process:** The Process tab now renders the flow as a graph — group cards keep all editing interactions (select, group menu, step right-click Modify/Break) but are laid out by dagre with real connections drawn as SVG edges (solid fall-through, labeled 是/否 condition branches, back-edges still guarded by the loop limit); AI-merged flows whose parts came from different recordings split into independent chains with their own Start/End and per-source color coding plus a legend.
- **Test:** Replay state overlays on the Process graph — step result dots and chips, group outlines (green/red/gray), walked edges highlighted and untaken branch edges dimmed — refreshing live during a run, while editing is blocked until replay stops; steps completed by AI takeover keep their AI badge.
- **Executor:** Steps can carry a `settle` option (`networkIdle` and/or `domQuietMs`, bounded by `maxMs`, default 10s) that lets the page become stable before the step runs, for the first action after slow transitions such as post-login first screens, big post-submit refreshes, or cross-system redirects; it is best-effort (never fails a step) and absent the field replay is unchanged.
- **Flow:** AI refinements from the AI pane now record their direct sources as `meta.sourceFlows` and annotate each step's `sourceFlowId` (inferred from element-library origins, unannotated steps inherit their neighbor), giving the graph its segmentation and colors; purely recorded flows are untouched.
- **UI (AI pane):** All clickable AI actions live in one quick-actions strip above the chat composer — the welcome options (Merge/Generate/Optimize), the refine preset form with free text and Continue, the "Run remaining steps with AI" takeover button, and group re-record/add-node actions; the panel body above shows information only, and the strip hides itself when nothing is available.
- **Test:** The AI-pane progress list groups steps by process group (number, name, and group status) matching the graph one-to-one; groups a branch skipped are dimmed with a "Skipped · 分支未走" chip.
- **Packaging:** The build produces `dist/renderer-vendor.js` (dagre vendored for the renderer, loaded before `app.js`); if it is missing, the Process panel shows an explicit error instead of a blank canvas.
- **Replay:** A step's `timeout` field now sets that step's assert/expect wait budget (default 5s, clamped to 1–30s), so checks after slow transitions such as SSO sign-in or a first app navigation can be told to wait longer before failing; `condition` steps likewise use `timeout` to widen their bounded re-evaluation window (see Fixed).
- **Process:** Group cards carry a branch badge stating when the group executes (for example "当「…」为 否 时执行", multiple conditions joined with semicolons) and condition steps get a dashed green outline, so branch structure is visible in the serial group list.
- **Recording:** Steps whose surviving target candidates are all structural selectors (no testid/role/label/text, only css-path/xpath level) are saved with `reviewRequired`/`reviewReason`, flagging replay-fragile steps at record time instead of discovering them after a failed replay; the flags also flow into AI refinement projections.
- **Recording:** Single-select dropdowns record as `select_N` Reference variables with the recorded value as default (multi-select keeps inline values), so replay-time dropdown choices are editable like text inputs.
- **Executor:** `isOptional` now applies to element steps too: when the target does not appear within a short wait, the step reports `skip` instead of failing, letting tolerant login groups absorb a remembered SSO session.
- **Pi:** AI takeover after a failed Test run: a one-click "Run remaining steps with AI" action hands the failed step and all remaining steps to a `@browser_use/pi` agent attached to the embedded browser (failure scene preserved); steps complete with an AI badge, progress lands in the AI pane chat, secrets flow through the SDK's redacting `sensitiveData` channel, and guardrails (domain allowlist from the flow, per-step retry, total time budget — now 15 minutes, Stop) bound the run. The source Flow is never modified.

### Changed

- **Process:** The canvas rendering engine is now AntV X6 3.1.8 (vendored via `window.__flowlinkX6` in `dist/renderer-vendor.js`) replacing the hand-written SVG/pan-zoom layer — `renderer/flow-graph.js` (flatten/buildGraph/layoutGraph + dagre) is unchanged and X6 consumes its node/edge/coordinate output; layout, parallel-chain segmentation and source coloring, diamond decision nodes, edge styles, replay overlay, menus, and refine messaging behave as before, and the engine swap adds an X6 MiniMap as the only new visible affordance. The vendor bundle grows from ~640 KB to ~1.94 MB (unminified IIFE) plus its existing CSS output.
- **AI pane (BREAKING):** Chat-driven generation intent now comes from the model — the advice prompt requires an `INTENT=refine|advice` verdict line that the renderer strips from the displayed text; a refine verdict resolves sources as @ attachment > currently open recording > the AI lists the task's saved recording names asking the user to @ reply (no saved recordings means a straight "nothing to refine"), and only then starts the generation pipeline (a missing or unparseable verdict falls back to advice plus a fixed hint "如需直接生成新版本，请明确说明或使用 Refine 表单"). The local keyword regex (`aiRequestNeedsMaterial`) and the sticky `aiSourceIds` source carry-over are gone — every chat message evaluates its own sources; the checked-recordings Refine button always generates, using the selection snapshot taken when the menu opened.
- **Takeover repair (BREAKING):** The automatic post-takeover repair of an already-REFINED recording no longer stages a pending version — it persists directly as version+1 with a history snapshot for rollback through the new `flow:directUpdate` IPC (a failure of the base version is not checked; the snapshot is the rollback); Record targets keep the `REPAIRED-` new-entry behavior.
- **UI (AI pane):** Stopping a recording no longer triggers any automatic AI interaction — the post-stop auto analysis calls (fallback and normal stop paths) are removed and the AI pane never opens by itself after a recording; every AI entry (quick-action presets, the Refine button, opening the pane) is user-initiated, and manual entries behave unchanged.
- **Flow (BREAKING):** Condition branch contract relaxed and renamed — branch fields are `trueStepId`/`falseStepId` targeting any existing step id in the same Flow (no longer top-level group ids), a condition may sit anywhere inside a group (no longer forced last), and a missing branch means sequential continuation instead of ending the run; the executor jumps straight to the target step (the skipped interval is reported as `skip`), the three-visit loop guard now counts an entry whenever the cursor lands inside a group from outside (including mid-group jumps), AI takeover gate routing follows the same semantics, and the Process graph extracts every in-group condition into a diamond decision node with edges to any target node plus sequential-continue default edges. Existing flows with old `trueGroupId`/`falseGroupId` fields must be deleted by hand — no migration (field semantics changed; no recorded flow used conditions at cutover).
- **Prompts:** Generation prompts no longer produce a dedicated Sign-in group — sign-in/SSO steps merge into the first business-stage group (entry navigation → optional gateway condition with sequential-continue default → `isOptional` tolerant credential steps → target-page assertion at the end), and the condition contract description (anywhere in group, default = sequential continue, target = any existing step) matches the new schema.
- **UI (AI pane):** The welcome options (merge/generate/optimize) no longer appear automatically on analysis tabs — clicking Refine shows them, choosing Optimize opens the preset+free-text form (merge/generate keep their existing flows), and switching page or workflow resets the menu; Test failures no longer auto-send an AI message or show a standalone takeover button — diagnosis and takeover happen only through the new presets.
- **Pi:** `pi:generateFlow`/`pi:repairFlow` failures now return the full error text labeled with the failing stage and underlying reason, and the AI pane shows it as an expandable error detail instead of asking the user to check log files.

- **Process:** All flow-graph edges are now solid lines — back-edges and untaken (dimmed) branch edges drop their dashed style, so line style no longer distinguishes edge kinds (color-based distinction is planned separately).
- **Instruction:** Step row text and post-recording step summaries now come from the single `processStepLabel` source (label first, synthesized fallback), so Instruction, Process, and Test agree; recordings without labels keep their existing synthesized wording.

- **Recording:** Recording no longer takes periodic screenshots — the 800 ms `capturePage` pipeline (and the renderer's canvas/MediaRecorder webm synthesis) is gone, removing the recording-time page flicker and lost clicks it caused; the list thumbnail now comes from a single poster screenshot taken shortly after recording starts.

- **Browser:** Opening the embedded browser for recording or a Test is now always a fresh browser session — extra tabs close and the start URL reloads unconditionally (an already-open same URL no longer keeps its stale DOM), and opening a taskflow's workspace while idle resets the browser to that flow's start URL, so tabs and page state no longer bleed across taskflows or runs; restarting during a replay is refused at the process boundary.

- **Recording:** Recorded navigation target URLs are saved as `url_N` Reference variables (default = the recorded URL), so users can retarget a flow — for example switch environment domains — from the Reference page before replay; replay behavior is unchanged because the default reproduces the recorded address.
- **Process:** Decision nodes render as true diamonds (clip-path polygon instead of a rotated rectangle), and edges route through dagre's computed bend points as polylines anchored to node boundaries — a decision's two outgoing branches leave one downward and one sideways (right or left), with diagonal and turning segments allowed — for a standard flowchart look.

- **Pi:** Generation prompts (auto-sanitize and refine) may mark the first action after a slow transition with `"settle": {"domQuietMs": 500}` or `"settle": {"networkIdle": true}` so the page settles before the step runs, alongside the existing `"timeout": 15000` guidance for post-login checks.
- **Test:** AI takeover progress events align by step id (`playback:aiStep` now carries `stepId`; the old index semantics remain as a fallback), and step flattening is a single shared implementation (`renderer/flow-graph.js`) used by the Test list, the Process graph, and all playback event handlers, so display order and result alignment can no longer drift apart.
- **Pi:** Generation prompts (auto-sanitize and refine) now enforce verification and branching invariants: login gates and post-navigation checks must target session-stable landmarks (a `urlChange` URL pattern first, then structural elements such as navigation/table containers) instead of volatile record data (order numbers, dates, list rows), and checks after slow transitions (SSO sign-in, first app navigation) are requested with `"timeout": 15000`.
- **Startup:** `npm start` / `npm run dev` now launch through a plain Node script (`scripts/start.mjs`) instead of the removed PowerShell launcher, so any shell (and coding agents) can start the app with the same flags (`--dev`, `--pi-system-proxy`, `--pi-proxy=<url>`; legacy spellings accepted); the launcher itself switches the Windows console code page to UTF-8 so Chinese logs stay readable in terminals and redirected output.
- **Recording:** Fingerprints no longer collect framework-internal attributes (`data-bind`, `data-reactid`, `data-v-*`, `ng-*`) or values containing line breaks, and the recorder backfills an approximate role/accessible name (implicit role from the tag, own text as name) when `ariaSnapshot` cannot supply one, so role+name candidates and a meaningful fingerprint exist even when the accessibility snapshot fails. Existing flows keep replaying: L2 attribute equality now compares the element's raw attribute values for the keys the recorded fingerprint supplies.
- **UI:** The Manual/Automated badge on Process canvas steps now marks step origin: recorded steps and steps added by users in the editor show Manual, while REFINED (AI-refined) flow steps show Automated.
- **UI:** Process, Instruction, and Test step text prefers the step's own label (AI-refined flows carry business-language labels) and otherwise renders Chinese phrases per operation type (点击 / 填写 / 选择 / 上传 …) instead of raw English kind names; the Instruction operation type is now a searchable picker styled like the Service Level selectors (search box, clear button, check mark on the selected option) limited to the supported step types, and fields without meaning for a type (target/value) are disabled.
- **Pi:** Auto-refined (`REFINED…`) workflows with a login segment now keep it as a gate condition plus a tolerant sign-in group (optional credential steps closed by an assert), so replays adapt to logged-in, expired, and remembered-SSO states; recorded value parameters (`input_N`/`select_N`/`password`/`file_N`) are preserved as templates, unknown variable references fail the generation, and unused variables no longer linger on the Reference page.

- **Recording:** Clicking Record no longer reloads the start URL when the embedded browser is already on it (hash differences ignored); the recording baseline is the current page, so use the browser toolbar reload first if a freshly loaded page is required.
- **UI:** Rebranded to the FlowLink green identity end to end: theme colors, header wordmark, navigation labels, and app title replace the previous blue/Taskflow look.
- **Packaging:** The window, taskbar, and packaged `FlowLink.exe` now show the FlowLink icon (multi-size `.ico` under `resources/`, verified by `package.mjs`); the renderer also ships an SVG favicon and logo under `renderer/assets/`.
- **UI:** Static page and panel structure (flow list rows, version rows, recording rows, analysis tabs, AI pane blocks) now lives in `renderer/index.html` templates that JavaScript fills, instead of being assembled from JS strings.
- **Recording:** Auth-shaped redirects (`sso_redirect`/`login_redirect`/`auto_redirect`) are retained in the raw evidence stream and the FlowForge sidecar with their navigation type; they never fold into the previous action's expectation and are kept out of the coalescer, so recorded click expectations are unchanged.
- **Flow:** Migrate existing schema v1 recordings to schema v2 for condition branches without changing their ordered replay behavior.
- **Storage:** Delete a recording's Flow and artifacts with the recording, remove all recordings' files when deleting a taskflow, and discard generated files when closing a new unsaved taskflow.

- **Recording:** Element crop screenshots are captured through a single CDP screencast frame (with the crop rectangle in a sidecar JSON, the evidence viewer crops client-side) instead of per-action clipped page screenshots, and the recorder no longer takes whole-page step screenshots at all — both were implicated in the remaining recording-time flicker; rrweb replay is the step-by-step view now, recordings made before the switch keep showing their existing step screenshots, and `FLOWLINK_DISABLE_RECORDER_SHOTS=1` skips element crops entirely as a diagnostic bisect switch.

- **Instruction:** Deleting a step from the per-step ⋯ menu is now a quick action — no confirmation dialog, a toast confirms the deleted step number, deleting the last step of a group removes the emptied group along with any condition branch references pointing at it, and the last step of the only group cannot be deleted (a Flow must keep at least one step).

### Removed

- **Process:** The proposal side-by-side compare view is gone — banner, dual graph panes with diff highlighting, Apply/Discard buttons, and their templates/styles — pending updates are resolved from the AI pane's Confirm/Discard with the textual change list instead of a graphical compare.
- **AI pane:** The label-only description polish is removed end to end — the "Optimize step descriptions (labels only)" refine preset, its label-only Pi generation with the old→new diff confirmation dialog, and the related template/styles are gone, leaving Refine as a single full-refine path (the Instruction surface is scheduled for a later redesign).
- **Pi:** Recording Stop no longer auto-generates a `REFINED…` twin — REFINED recordings now come only from an explicit Refine in the AI pane; the `autoRefine` setting (a stale `autoRefine` key in `config/pi-settings.json` is tolerated and ignored) and the `ai:autoRefine` event are removed.
- **Recording:** The `recording:saveVideo` IPC and the renderer's frame-consumer channel are removed with the old video pipeline; existing webm files on disk are unaffected.

### Fixed

- **AI:** Chat requests that ask for a workflow change no longer dead-loop between a narrow local keyword regex and the advice prompt's "do not generate" instruction (the model's intent verdict replaces the regex), and the sticky source list no longer silently refines a different recording than the user selected — sources are resolved explicitly per message (@ attachment > currently open > ask by name).
- **Pi:** Transport-class model request failures ("other side closed", socket hang up, ECONNRESET/ECONNREFUSED, fetch failed — but not timeouts) are automatically retried once after 1 s; a still-failing retry returns an actionable Chinese message pointing at the local proxy idle timeout (raise the proxy idle/response timeout to ≥300 s and retry) instead of a raw transport error.
- **Process:** Step and group right-click menus show again — every group card carried the graph node id (`g1-part0` style, unconditionally suffixed by `FlowGraph.buildGraph`) in `data-canvas-group`, while both menu handlers looked the value up in the process groups by real group id (`g1`) and silently returned when nothing matched, so neither menu could ever open on any card (the same mismatch also broke body-click group selection highlight and the group-action bar positioning lookup); cards now carry the group id (`node.groupId || node.id`), the one value every reader already agrees on.
- **UI (Record):** rrweb replay no longer black-screens — mounting the player no longer re-inserts the per-tab player containers into the stage (that removal destroyed each replay iframe's document, so rrweb 2.2's sandboxed-iframe rebuild registration went stale and every full-snapshot rebuild failed silently, leaving a correctly sized but forever-empty iframe over the dark stage); the first frame now paints right after mount, the "回放诊断" report additionally probes the replay iframe's built document (readyState, body children, stylesheets, background) for one-click black-screen evidence, and the diagnosis ran against the user's real recording through the app's own CDP port.
- **Process:** Context menus position correctly under canvas pan and zoom — step and group menus use window-fixed viewport coordinates clamped to the window (no more offset or clipped-away menus at e.g. 60% zoom), and click-outside or Esc closes a menu without triggering other canvas behavior.
- **Pi:** Default Refine again restructures the login segment unconditionally — refine and autoSanitize prompts actively rebuild any login/SSO segment into the first business-stage group (entry navigation → gateway condition whose `trueStepId` targets the first business step after the credentials, missing branch = sequential continue → `isOptional` tolerant credential steps → target-page assert with `timeout: 15000`) even when the instruction never mentions login; the conditional "if the instruction touches the login segment" wording is gone and the system prompt contract matches.
- **Pi:** Refine no longer crashes with "Cannot read properties of undefined (reading 'kind')" when the model emits assert/condition steps without an assertion definition — such steps are now dropped with a risk note ("模型输出的校验步骤 X 缺少断言定义，已移除") so refinement still produces a result (model-added checks are enhancements, not recorded evidence); regression covered by `scratch-refine-repro/crashtest.mjs`.
- **UI (Record):** rrweb replay no longer black-screens inside the app — the player checks whether the vendored rrweb stylesheet actually applied (`.replayer-mouse-tail` positioning), injects a fallback inline positioning set (wrapper/iframe/mouse-tail) with a console warning when it didn't, filters out tab streams without a full snapshot (they can never paint), and shows an explicit error block instead of a silent black stage when styles and rendering both fail.
- **UI (AI pane):** Typing in the refine free-text no longer resets checked presets — the form DOM is built once per refine mode (input-time re-renders don't rebuild it) and checkbox state lives in UI state behind the chips.
- **Test:** Login-gate `condition` steps no longer misjudge an already-signed-in session as logged-out when the SPA has not finished rendering after the preceding navigation — conditions now re-evaluate within a bounded window (default 4 s, every 300 ms, any match wins; per-step `timeout` widens it, clamped 1–30 s, retries logged) instead of one instantaneous check, so the run goes straight to the business group when the landmark appears late; `assert`/`expect` keep their existing wait semantics.
- **Recording:** rrweb capture no longer goes silent after an in-tab navigation — the injected script spins in-page (200 ms × 25) when the event binding is not yet exposed in the new document, and a main-frame `framenavigated` watchdog re-boots recording after every navigation while rebuilding the CDP session and its init-script registration if that session died; the manifest now records each tab's last-event time (refreshed at least every 5 s) so a dead event stream is diagnosable from disk.
- **Record:** In-app replay no longer stages a black player because the iframe was measured at 0×0 before it finished rendering asynchronously — the player polls (rAF with a 120 ms timeout fallback, ≤3 s) until the replay iframe has a non-zero rect before computing scale and stage height, shows a loading notice meanwhile, and falls back to default dimensions only on timeout.
- **Record:** rrweb replay no longer shows a black stage — the Replayer's base styles (`.replayer-*`) now ship with the vendor bundle (`dist/renderer-vendor.css`, linked from the app page) and the stage carries defensive positioning so a missing stylesheet degrades the layout instead of pushing the replay iframe out of view.
- **Test:** Intermittent "无法加载页面" on Test start is eliminated: when the first executable step is a `navigate`, the pre-run browser reset no longer issues its own load (the step's navigation is the only one in flight), otherwise the reset now waits for its load to finish (bounded 10 s) before handing the page to the executor, and a `navigate` step retries once on failure (including `net::ERR_ABORTED`), matching the start-URL open's retry semantics.

- **Instruction:** Edits on the Instruction tab now truly persist — they previously only mutated a local draft that a loaded Flow's Test ignored, and the draft-rebuild path forged a single-text-candidate target so editing "目标" silently discarded the recorded evidence chain; that path is removed and all editing goes through the Flow loaded on tab open and the validated update contract, with unsaved edits flushed when switching tabs and tests rebuilt from the same flattened step index.
- **Test:** The taskflow list's Run action now goes through the same entry as the Test panel — it initializes the step list and run flags and switches the view to Test before replaying; previously the replay ran in the background with no UI feedback because progress events were dropped (the item's run flags were never set).
- **Test:** A second run of the same flow (or a flow whose start URL matches where the previous run ended) no longer stalls on an unopened start page — the pre-run reset previously skipped reloading when the browser already sat on that URL, while the embedded executor trusts that reset as its only load.

- **Process:** The step right-click "Break" action works on saved flows again — it split only a derived view array that the group list rebuilds from the real steps, so nothing changed; it now splits the actual group in the Flow and persists through the validated update contract, rolling back with a warning notice on failure.

### Security

- **Recording:** Password inputs are always masked in the rrweb capture (`maskInputOptions`), matching the product's secret-handling policy.
- Storage-state handling preserves raw or wrapped profile shapes and treats credentials as sensitive data.
- **Dependencies:** The vulnerable `undici` 8.9.0 (high) and `minimatch` 10.2.5 (moderate) copies pinned inside `@browser_use/pi` — the source of every remaining `npm audit` finding — are overridden to the versions the rest of the app already uses (8.12.3 and 11.0.3), so packaged builds stop shipping them; AI takeover behavior is unchanged.
